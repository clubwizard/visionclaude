Getting started

Aside lets you talk to Claude with your voice, optionally with vision from your camera. Everything is per-account: your API keys, conversation history, MCP connectors, and custom skills are all isolated from other users on this server.

The 90-second setup

  1. Go to /account and paste your Anthropic API key. Hit Test to confirm it works. This is the one required key — without it, nothing can talk to Claude.
  2. (Optional) Paste a Deepgram or OpenAI key for high-quality text-to-speech. Without either, the voice client falls back to your browser's built-in TTS (works, but sounds robotic).
  3. Go to /app and tap Talk. Say something.

API keys

All keys are encrypted at rest with the server's master key. The server can only decrypt them at request time, and never sends them back to your browser.

Anthropic (required)

This is what powers Claude itself. You pay Anthropic directly for what you use — Aside just relays.

Where to get one
console.anthropic.com/settings/keys → New API key → copy → paste into the Anthropic field on /account.
What it looks like
sk-ant-api03-AbC...XyZ

Deepgram (optional, recommended)

High-quality, low-latency text-to-speech (the Aura voices) and speech-to-text. The default voice on /app.

Where to get one
console.deepgram.com → sign up → API Keys → create.
What it looks like
a1b2c3d4e5f67890abcdef1234567890

OpenAI (optional)

An alternative set of TTS voices (Alloy, Nova, Echo, …). More expressive than Deepgram, slightly slower. Useful if you want a specific voice character.

Where to get one
platform.openai.com/api-keys → Create new secret key.

Voice client

Open /app on your phone or computer. Grant camera + microphone permission when prompted.

How a turn works

  1. Tap Talk. The mic activates.
  2. Speak normally. When you pause, the recording stops and the transcript is sent to Claude.
  3. If Camera on is checked, the current frame is included as vision context.
  4. Claude responds. The TTS plays automatically through your speakers/headphones.
  5. Tap Talk again for the next turn (the conversation continues until you reload).

Example things to try

  • Point your camera at a label and ask "What does this say?"
  • Show Claude a recipe and ask "Convert this to grams."
  • Show a stack trace on your screen and ask "What's wrong here?"
  • Just chat — vision is optional, you don't need to point the camera at anything.

Choosing a voice

The Voice dropdown lists every voice your configured keys unlock. With only Deepgram set you'll see 10 Aura-2 voices; with OpenAI too, 20. Selection is saved in your browser.

iPhone app

Three paths to running Aside on your iPhone, easiest first. Pick based on whether you want Meta Ray-Ban support.

Path A — web client as a home-screen app (zero install, 30 seconds)

This is what most people should start with. Same camera + microphone APIs as the native app; only Ray-Ban pairing and reliable background audio are unavailable in this mode.

  1. Open https://your-aside-domain/app in Safari on your iPhone (must be Safari — Chrome on iOS can't be added to Home Screen).
  2. Tap the Share icon (square with up-arrow) → Add to Home Screen.
  3. Name it (Aside) and tap Add. You now have an icon that opens straight into the voice client.
  4. The first time you tap Talk, Safari prompts for microphone permission. Grant it. Tap the camera icon and grant camera permission too.
  5. Log in with your Aside email + password. Done.
What works on the PWA
Voice in (Apple's on-device speech recognition), voice out (any provider voice you've configured + browser fallback), camera frame capture, vision toggle, conversation history, voice picker, skills, MCP connectors. Identical to desktop browser experience.
What doesn't
Meta Ray-Ban Bluetooth (no Web Bluetooth in iOS Safari). Reliable background audio (Safari pauses audio after ~30 seconds backgrounded). Push notifications.

Path B — Build & sideload via Xcode (free, requires a Mac)

Native app for Ray-Ban support and reliable backgrounded audio. With a free Apple ID the signed build expires every 7 days; plug your phone in and rebuild to refresh. Paid Developer account ($99/yr) extends to a year.

Prerequisites:

  • macOS 14+ with Xcode 15+ (free from the Mac App Store)
  • An Apple ID (free)
  • iPhone running iOS 17+ with a Lightning or USB-C cable
  • xcodegen installed: brew install xcodegen

Step-by-step:

  1. Clone the Aside repository on your Mac (operator has the URL).
  2. Regenerate the Xcode project and open it: 
    cd ClaudeVision/ios
xcodegen generate
open ClaudeVision.xcodeproj
  3. Plug your iPhone into your Mac via USB. Unlock the phone and tap Trust This Computer on the iPhone prompt.
  4. In Xcode's toolbar, select your iPhone in the device dropdown (it appears once Trust is granted).
  5. Click the project in the left sidebar → the Aside target → Signing & Capabilities. Click Team → Add an Account → sign in with your Apple ID.
  6. Change the Bundle Identifier to something unique — e.g. com.yourname.aside. The default com.aside.app may conflict if someone else built it before you on the same Apple ID.
  7. Hit ⌘R. Xcode builds, signs, and installs.
  8. On the iPhone the first launch will fail with "Untrusted Developer". That's expected. Open Settings → General → VPN & Device Management, find your Apple ID under Developer App, tap Trust.
  9. Re-launch the app from the Home Screen. It opens.
Common Xcode build errors: If you get "No signing certificate", the bundle identifier you chose is already in use under your Apple ID — change it. If you get "requires a development team", you haven't set Team in Signing & Capabilities. If you get "could not connect to the iPhone", unplug and replug the USB cable, then re-trust.

Path C — TestFlight (paid, polished, for inviting others)

If you have an Apple Developer account ($99/yr), Xcode → Product → Archive → Distribute App → App Store Connect → upload. Then in App Store Connect → TestFlight → invite testers via email. They install Apple's official TestFlight app and get the build. No expiry, no plugging in cables.

Authentication options for Gateway mode

Option A — session cookie. The app opens an in-app web view, you log in with your email + password just like in a desktop browser. The session cookie persists for 24 hours. When it expires, the app prompts you to log in again. Best if multiple people share an iPhone (the cookie can be cleared).

Option B — gateway API key. A single long-lived secret you generate on the server and paste into the iOS app. No login required, no cookie expiry. Best if the phone is always you. The operator runs:

openssl rand -hex 32  # generate a 64-char hex string
# Add to .env on the server:
GATEWAY_API_KEY=<the hex string>
# Restart:
docker compose restart

Then in the iOS app → Settings → Gateway API key → paste the hex string. The app now sends X-Gateway-Key on every request.

Same Aside, same account. Either way the iOS app talks to the same backend your browser does. Your conversation history, MCP connectors, and skills follow you between devices. Switching devices doesn't lose context.

Connecting Meta Ray-Ban glasses

Only available in the native iOS app (Bluetooth APIs aren't exposed to web pages).

  1. Pair the glasses in Meta View first. The official Meta View app handles the initial Bluetooth pairing. Aside consumes the existing pairing; it can't initiate one.
  2. Open Aside → Settings → scroll to Meta Ray-Ban Glasses.
  3. Tap Register. The Wearables Device Access Toolkit lists your paired glasses.
  4. Select the pair. Status shows Connected. From now on, Aside can pull camera frames from the glasses instead of the iPhone camera.
  5. In the voice client header, the camera source toggles between iPhone and Ray-Ban.

The glasses don't have a built-in microphone exposed to third-party apps yet (Meta's API gates this). Voice still goes through the iPhone microphone. The glasses contribute camera frames only — but those frames are 720p with open-ear audio context that's hard to match holding a phone up.

Behavior notes

  • Backgrounded audio — the native app holds an audio session and continues playing TTS when you lock the screen or switch apps. The PWA can't reliably do this; iOS suspends Safari audio after ~30 seconds.
  • Battery — continuous frame capture is the expensive part. With camera on at 1Hz, expect ~15% battery per hour on a recent iPhone. Voice-only (camera toggled off) is barely measurable.
  • Connectivity — the app handles brief network drops automatically (it re-queues the next message). If your Aside server is unreachable for >30s, you'll see a banner; turns are dropped, not buffered.

Skills

Skills are short prompts you install to specialize how Claude responds for you. Think of them as personal preferences Claude follows in specific situations — without you having to repeat yourself every turn.

Each skill has four parts:

FieldWhat it does
NameShort identifier you'll recognize. ≤64 chars.
DescriptionOne line telling Claude what the skill does. ≤280 chars. Always in the system prompt so Claude knows the skill exists.
TriggerComma-separated keywords. When your message contains one, the full body is injected. Empty = advertised but never auto-injected.
BodyThe actual instructions Claude follows when triggered. ≤8 KB.

Example: recipe converter

Name
Recipe converter
Description
Convert cooking volumes to grams using standard density tables.
Trigger
recipe, convert, grams, cups, tbsp, tsp
Body
When the user mentions a cooking quantity in volume
(cups, tbsp, tsp, ml), convert it to grams using standard
density tables. Show the conversion factor briefly.
Example: "2 cups flour ≈ 240g (1 cup ≈ 120g)".

Example: meeting summarizer

Name
Meeting notes
Description
Summarize meeting transcripts into actions, decisions, and open questions.
Trigger
meeting, summarize, action items, recap
Body
When given a meeting transcript or notes, produce three
sections:
- Decisions (what was agreed)
- Actions (who owes what by when)
- Open questions (unresolved items)
Keep each bullet to one line. Use names not pronouns.

Example: shopping mode

Name
Shopping
Description
When shown a product, read price, brand, key specs.
Trigger
(empty — always advertised, body never auto-injected)
Body
When the user points the camera at a product label or
price tag, extract: brand, model/variant, price (with
currency), and any key specs visible. Prefer reading
the actual visible text over inference.

A skill with no trigger is always advertised in Claude's system prompt but the body is never auto-included. Use this when the skill applies broadly and you want Claude to know about it always.

Token cost. Every enabled skill's description sits in your system prompt on every turn. Bodies only ride along when their trigger fires. So 20 skills with 200-char descriptions ≈ 4 KB extra header; a triggered 2 KB body adds another 2 KB just for that turn. Practical limit is around 30 skills before you start feeling it in latency.

MCP connectors

An MCP server is a hosted endpoint that exposes tools (send_message, search_repos, query_database…) over HTTP. When you add one, its tools become available to Claude on your next chat — scoped to your account only.

Two requirements for a connector to work here:

  • The endpoint must use https:// (plain http and private IPs are blocked)
  • It must speak the MCP protocol over HTTP (Streamable HTTP or SSE)
About OAuth. Many hosted MCP services (Notion, GitHub, Linear, Sentry, Atlassian) advertise OAuth as the "official" auth flow. Aside currently sends a static Authorization header — it doesn't drive the OAuth dance for you. All of those services also issue long-lived tokens (integration secrets, personal access tokens, API keys) you can paste here directly. The examples below show the static-token path for each.

Real services you can connect right now

These are working URLs at the time of writing. Each row shows the endpoint, how to get a static token from that service's dashboard, and the exact Auth header value to paste.

GitHub https://api.githubcopilot.com/mcp Bearer ghp_… github.com/settings/tokens → Generate (classic, with repo + read:org)
Linear https://mcp.linear.app/sse Bearer lin_api_… linear.app/settings/api → Create new API key
Sentry https://mcp.sentry.dev/sse Bearer sntrys_… sentry.io → User → Auth Tokens → Create New Token

Worked example: connect Notion

  1. Visit notion.so/profile/integrations and click New integration. Give it a name (e.g. "Aside"). Submit.
  2. Copy the Internal Integration Secret — it starts with secret_.
  3. Open the Notion pages or databases you want Aside to access, click Share, and add the integration.
  4. On Aside's /account page → Your MCP connectors → + Add a connector, paste:
    Name
    My Notion
    URL
    https://mcp.notion.com/sse
    Auth header
    Bearer secret_ + your integration secret
  5. Hit Save connector, then Test on the new row. You should see "Connected. N tools available."
  6. Go to /app and say something like "Find my notes about the Edinburgh trip in Notion" — Claude can now invoke the Notion tools.

Worked example: self-hosted MCP behind your own URL

If you run your own MCP server (or wrap a stdio MCP with supergateway so it speaks HTTP), point Aside at it the same way.

Testing a connector

After saving, hit the Test button on the row. The server opens a probe connection to your URL, lists the tools it advertises, and reports back. You'll see "Connected. N tools available." on success or a clear error if it fails (bad URL, bad auth, server offline, timeout).

What happens during a chat

  1. Your enabled connectors stay disconnected until you actually use them.
  2. On your first /chat after enabling one, Aside opens a connection, lists tools, and merges them into the tool set Claude sees.
  3. Connections are cached per user. If you go idle for 10 minutes, the connection is dropped (auto-reopened on next use).
  4. Each tool call has a 30-second timeout. If your connector hangs, the request fails cleanly instead of blocking the whole chat.
Not seeing your tools in Claude's responses? Claude only invokes tools when it judges them relevant. Mention the tool explicitly ("check my Notion for the meeting note") or hit Test on the connector row first to confirm it's reachable.

Claude Desktop & Cowork

Cowork is Claude Desktop's agent mode, launched March 2026. Unlike chatting with Claude in the web app or the API, Cowork runs locally on your Mac and can use your filesystem, browser, computer-use, and any MCP servers you've configured — it acts on things for you, not just talks about them. Dispatch is the companion feature that pairs your phone (via QR code in Anthropic's mobile app) to a desktop Cowork session, so you can drive the agent from anywhere.

Aside ships in two pieces:

ModeWhat it isWho runs it
Gateway The hosted multi-user web service you're using right now. Talks directly to Anthropic's API; has its own accounts, keys, conversation history. This help page is served from a Gateway. The operator runs one Gateway; everyone shares it.
Channel A small server you run on your own Mac alongside Claude Desktop. It registers as an MCP server with Cowork, giving the desktop agent eyes and ears through your iPhone or Ray-Ban glasses. Each user runs their own Channel on their own Mac.

If you want to use Cowork (rather than the hosted Gateway you're on now) for actual work tasks — and have your phone be its sensors — set up Channel mode on your Mac. The two modes coexist; you can use whichever fits the task.

How Channel mode bridges to Cowork

When you wire Aside's Channel server into claude_desktop_config.json, Cowork gains four new MCP tools that let it talk to your phone:

ToolWhat Cowork can do with it
replySend a text reply back to the phone (with optional TTS audio). Cowork's natural-feeling responses.
edit_messageEdit a previously-sent reply. For corrections mid-thought.
get_camera_snapshotPull a fresh photo from the user's active camera. Cowork can ask "show me what you're looking at" mid-task.
request_voice_inputSpeak a clarifying question via TTS and wait for the user's spoken reply. Returns the transcribed text inline.

So for example, you say "book the train to Edinburgh on Thursday"; Cowork browses to the train booking site, gets to checkout, then calls request_voice_input to ask "Should I use the Sainsbury's card or the Monzo one?". You answer naturally and Cowork completes the booking — without you needing to look at the Mac.

Setting up Channel mode on your Mac

This is independent of the hosted Gateway you're on right now. You need:

  • A Mac running macOS 14+ with Claude Desktop installed
  • An Anthropic Pro or Max subscription (Cowork isn't on Free)
  • bun installed: curl -fsSL https://bun.sh/install | bash
  • A clone of the Aside repository on the Mac

Step-by-step:

  1. Boot the Channel server standalone once to verify it works: 
    cd ~/aside/ClaudeVision/channel
bun install
bun server.ts
    You should see a startup banner with a generated channel token. Ctrl-C to stop.
  2. Edit Claude Desktop's MCP config at ~/Library/Application Support/Claude/claude_desktop_config.json (Windows: %APPDATA%\Claude\). Add (merge — do not replace any existing mcpServers block): 
    {
  "mcpServers": {
    "aside": {
      "command": "bun",
      "args": [
        "run",
        "/Users/you/aside/ClaudeVision/channel/server.ts"
      ]
    }
  }
}
    Use the absolute path. If bun isn't on Claude Desktop's PATH, use the absolute path to bun too (which bun to find it).
  3. Fully quit and reopen Claude Desktop (⌘Q — closing the window isn't enough). MCP servers are only loaded on startup.
  4. Verify the tools loaded — in a new Cowork chat, ask "What MCP tools do you have?". You should see reply, edit_message, get_camera_snapshot, request_voice_input in the list alongside any other MCP servers.
  5. Find the channel token for the iPhone — either open the dashboard at http://localhost:18790 in Safari on the Mac, or: 
    cat ~/.claude/channels/aside/.channel-token
  6. On your iPhone, open the Aside app → Settings → switch Mode to Channel. Enter:
    • Host: your Mac's LAN IP (the dashboard at http://localhost:18790 shows it; or System Settings → Wi-Fi → Details)
    • Port: 18790
    • Channel Token: paste from step 5
    Tap Connect — green indicator means wired up.
Mac and iPhone must be on the same Wi-Fi network for the iPhone to reach localhost:18790 on the Mac. Guest networks often have AP isolation that blocks this — switch to your main network or run a hotspot the Mac also joins.

(Optional) Pairing Dispatch alongside

Dispatch is Anthropic's QR-pair feature that lets you drive your Mac's Cowork session from Anthropic's official mobile app. Install Anthropic's mobile app, scan the QR from Claude Desktop's pairing UI, done.

Dispatch and Aside Channel mode are complementary, not competing:

  • Dispatch = your phone is a chat-style remote control for the Mac's Cowork agent
  • Aside Channel = your phone is sensors (camera, voice) Cowork can use during any task, including ones initiated via Dispatch

Use both at once and you get the killer flow: you're walking around with the Anthropic app and your Aside iPhone connected. You ask Cowork (via Dispatch) to do something; mid-task it needs to see a thing — it calls get_camera_snapshot through Aside's MCP server, your phone takes the photo, the answer goes back to Cowork. You never touched the Mac.

State on disk (Channel mode)

The Channel server keeps state at ~/.claude/channels/aside/ on the Mac:

  • inbox/ — images uploaded from the phone
  • outbox/ — TTS audio and files Cowork pushes back
  • .env — ElevenLabs key (configured via the dashboard)
  • .channel-token — the shared secret with the iPhone (mode 0600)

You can delete inbox/ periodically if disk space matters; it's not auto-cleaned.

Password reset

Two paths:

1. Forgot password link (recommended)

  1. On the login modal, click "Forgot your password?"
  2. Enter your email. A reset link is sent.
  3. Click the link within 1 hour. Set your new password.
  4. Log in with the new password.

A successful reset invalidates your sessions on every other device. If you reset on your phone, your laptop session gets logged out on its next request.

2. Operator override

If email isn't configured on this server, the operator can reset your password via CLI. Ask them.

Troubleshooting

"No Anthropic API key configured"

Go to /account, paste your sk-ant-... key, hit Save. The Anthropic key is the only required one — without it nothing can talk to Claude.

Voice client says "Voice list unavailable" or shows no voices

The voice dropdown is built from your configured TTS keys. Add a Deepgram or OpenAI key on /account. Without either, the browser falls back to its built-in TTS (works, but no provider voices).

MCP connector test fails with "Connection failed"

  • Double-check the URL is reachable from a browser (curl -I https://your-url)
  • Confirm the auth header format the service expects (most want Bearer xxx; some want just xxx)
  • Make sure the server actually speaks MCP at that endpoint — many APIs are HTTP but not MCP

Claude's response is slow

Each tool call costs a round-trip to the MCP server hosting it. If a connector is slow, every chat that uses it inherits that latency. Test your connectors individually to find the slow one and disable or remove it.

Channel mode: "What MCP tools do you have?" doesn't list Aside's tools

  • Did you fully quit Claude Desktop with ⌘Q before reopening? Closing the window keeps the process running and MCP servers don't reload.
  • Check the path to server.ts in claude_desktop_config.json is absolute and correct (ls -la <path> should find it).
  • If bun isn't on Claude Desktop's PATH, use the absolute path: which bun to find it, then replace "bun" with that path in the config.
  • Read Claude Desktop's MCP log at ~/Library/Logs/Claude/mcp.log for the actual startup error.

Channel mode: iPhone won't connect to Mac

  • Are both on the same Wi-Fi network? Mac on wired Ethernet + phone on Wi-Fi often counts as different networks.
  • Guest network with AP isolation will block this. Switch to a non-isolated network or run a hotspot the Mac also joins.
  • Verify the Mac's LAN IP — it changes on network switches.
  • Confirm the Channel server is actually running: open http://localhost:18790 on the Mac.

I added a skill but Claude doesn't seem to use it

  • Check the skill is enabled (toggle on the row)
  • Make sure your trigger keywords actually appear in your message. Case doesn't matter but exact substring does — "convert" won't match "converted"
  • Try making the description more imperative ("ALWAYS convert..." vs "Sometimes convert...")

Got logged out unexpectedly

If you reset your password on another device, your other sessions are invalidated on their next request. Just log in again — it's by design.

Users seeing nginx's "502 Bad Gateway" during a deploy

If you (the operator) are deploying via ./deploy.sh and users see the raw nginx 502 page during the ~10s rebuild window, you're missing the maintenance-page fallback. The Aside repo ships deploy/maintenance.html (a friendly auto-retrying page) and deploy/README.md (the nginx snippet to wire it up). Drop the HTML somewhere on the host, paste the error_page block into Plesk's Additional nginx directives, and 502/503/504 will serve the friendly page instead. The page polls /health every 5s and auto-reloads users back into the app the moment the new container is healthy.

"Too many login attempts" / 429 error on login

The login endpoint allows 5 attempts per minute per IP — brute-force protection. If you legitimately hit it (forgot which password you used, typo'd a few times), the login dialog now offers an "Email me a reset link" button inline so you don't have to wait the minute out. If you'd rather wait, the countdown ticks down on the same dialog.

Reading endpoints (page refreshes, session checks) are NOT counted against this limit — only login, signup, forgot-password, and reset-password are. If you find normal navigation locking you out, ask the operator to check the logs.

Something else

Ask the operator of this server. The system administrator has access to server logs and can see what failed.
